2026-06-23 — Analyzer: rule-vs-existing-policy coverage check
  Prompt: also let the analyzer take the existing policy (same format as
  sample_policy.csv) and tell me if I just need to add something to an
  existing rule instead of creating a new one.
  Outcome (app.py):
    - New engine section "RULE-vs-POLICY COVERAGE MATCH": match_rules_to_policy()
      cross-references each analyze() rule against the existing policy's
      ENABLED ALLOW rules. Path (src->dst) matching is IP-aware via
      _object_network() + subnet containment; 'Any' covers all. Service
      objects are named/opaque, so service coverage is best-effort
      (_policy_service_state): Any/ALL_* and a literal port-number hit = "ok",
      else "unknown" -> "verify/add". Per rule status: covered / amend / new.
      coverage_to_csv() exports the report.
    - /analyze now accepts an OPTIONAL second file field "policy"; when present
      it adds {coverage, summary} to the JSON (backward compatible without it).
      New /coverage_download endpoint returns policy_coverage.csv.
    - ANALYZER_HTML: optional policy dropzone in the Input card; new
      "03 - Policy Coverage" card (hidden until coverage returned) with status
      pills (covered/amend/new), summary stats, and CSV download. escapeHtml()
      used for the policy-derived cells.
  Verified: ast parse OK; engine unit test (synthetic policy) hits all of
  covered/amend/new and ignores disabled rules; Flask test-client confirms
  /analyze with+without policy and /coverage_download.

2026-08-06  QA pass over the three changes above
  Prompt: "perform a full QA of your work please".
  Findings and fixes:

      10.5.9.1, 10.5.9.10, 10.5.9.11, 10.5.9.2 ... Harmless when sources were
      collapsed, glaring once every host gets its own row. Added
      _addr_sort_key() (numeric by IP version/address/prefix, non-IP values
      last) and used it for both the intra-rule source sort and the final rule
      sort. Proved by re-implementing the ORIGINAL algorithm and diffing:
      consolidated output is rule-for-rule identical, only ordering changed.
    - BUG (UI): the .selected highlight was only updated on 'change', so a soft
      reload that restored the user's radio left the highlight on the default.
      Extracted syncModeUI() and call it once on load.
    - Polish: .mode-option got position:relative and a :focus-within outline
      (the radio is opacity:0, so the label has to carry the focus ring).
    - DOC DRIFT: README.md still said ">10 objects" for the permissive check.
      Updated to ">50 objects" + "enabled", documented the new Output Detail
